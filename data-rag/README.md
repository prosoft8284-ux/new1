# data-rag — OCR و جست‌وجوی ترکیبی برای کتاب‌های فارسی/عربی

پایپ‌لاین کامل و رایگان برای اینکه هزار کتاب PDF (بیشتر عکسی) را یک‌بار OCR کنی و بعد با
سرعت میلی‌ثانیه از داخلشان جست‌وجو کنی — بدون GPU، بدون سرویس ابری، بدون کارت بانکی.

## نصب

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt      # یا: pip install -e .[embed]
bash setup_tesseract.sh                        # Tesseract پرتابل + مدل‌های fas/ara/eng
```

`setup_tesseract.sh` همه‌چیز را در `~/tools` می‌ریزد و به root نیاز ندارد:
`~/tools/squashfs-root/AppRun` باینری، `~/tools/fast` و `~/tools/best` مدل‌ها.
اگر جای دیگری نصب کردی: `export TESSDATA_PREFIX=/path/to/models`.

## شروع سریع

```bash
# ۱) کتاب‌ها را در books/ بگذار، بعد:
.venv/bin/python -m rag library --dir books

# ۲) جست‌وجو
.venv/bin/python -m rag search "انقلاب مشروطه" -k 5
.venv/bin/python -m rag search "السلطة" --lang ar
.venv/bin/python -m rag search "قاجار" --context          # پرامپت آماده برای LLM

# ۳) آمار
.venv/bin/python -m rag stats
```

`library` قابل ادامه است: هر بار اجرا کنی، کتاب‌های تمام‌شده رد می‌شوند، صفحه‌های
OCR‌شده از کش خوانده می‌شوند و فقط باقی کار انجام می‌شود.

## راه‌اندازی مجدد و اجرای طولانی

```bash
bash scripts/setup.sh            # اگر آماده باشد کاری نمی‌کند؛ با --force از صفر
bash scripts/ocr-all.sh books    # تا تمام‌شدن صف، خودش دوباره ادامه می‌دهد
.venv/bin/python -m rag status   # پیشرفت، صف، کتاب‌های مشکوک — بدون خواندن لاگ
```

`ocr-all.sh` برای همین ساخته شده که اجرای ۱۰۰۰ کتابی وسط کار قطع می‌شود (ری‌استارت
ماشین، تایم‌اوت، ماشین reclaim‌شده). هر بار که `library` می‌میرد، دوباره صدایش می‌زند و
چون کش صفحه‌ها و مانیفست روی دیسک است، ادامه از محل قطع تقریباً رایگان است. لاگ در
`data/library.log` می‌رود و `rag status` از `data/library-progress.json` می‌خواند.

## دستورها

| دستور | کار |
|---|---|
| `library --dir books` | OCR دسته‌ای + ایندکس، قابل ادامه، با ETA |
| `library --only '*تاریخ*' --force` | فقط کتاب‌های منطبق را دوباره پردازش کن |
| `library --exclude '*draft*'` | کتاب‌های منطبق را نادیده بگیر |
| `ingest --input x.jsonl` | ایندکس هر داده متنی (jsonl/json/csv/parquet) |
| `ingest-pdf --input a.pdf --index` | یک PDF + ایندکس |
| `search "..."` | جست‌وجوی ترکیبی با فیلتر دسته/زبان/سال |
| `remove --book 'a.pdf'` | حذف کامل یک کتاب از پارکت، بردارها و کورپوس |
| `serve --port 8765` | سرویس HTTP محلی (`POST /search`, `POST /context`) |
| `mcp` | سرور MCP روی stdio برای وصل‌شدن به دستیار |
| `status` | پیشرفت کتابخانه، صف باقی‌مانده و کتاب‌های مشکوک (بدون خواندن لاگ) |
| `stats` | آمار کورپوس و ایندکس |

## معماری

```
PDF ──(PyMuPDF, PGM روی stdin)──> Tesseract ──> کش صفحه‌به‌صفحه (data/ocr)
                                                    │
                            JSONL یک سند به ازای هر صفحه
                                                    │
        ┌───────────────────────────────────────────┴──────────────┐
   Parquet پارتیشن‌بندی‌شده (متن خام)                    LanceDB (بردارها)
   data/raw/category=…/year=…/part-*.parquet            data/idx/lance
        │                                                          │
        └── DuckDB (فیلتر + متنی) ──┐        ┌── ANN (IVF_HNSW_SQ) ──┘
                                    └── RRF ──> نتایج با استناد صفحه
```

متن فقط یک‌بار ذخیره می‌شود (Parquet)؛ ایندکس برداری فقط شناسه و ستون‌های فیلتر را
نگه می‌دارد. استنادها صفحه‌سطحی‌اند: `source = book.pdf#page=42`.

## تنظیم‌ها

| گزینه | پیش‌فرض | چرا |
|---|---|---|
| `--model fast|best` | `fast` | ۲.۳ برابر سریع‌تر، دقت تقریباً برابر روی چاپی |
| `--dpi auto` | رزولوشن بومی اسکن | بزرگ‌کردن مصنوعی فقط کندتر می‌کند |
| `--psm 6` | تک‌ستونه | برای کتاب دوستونه `1` را امتحان کن |
| `--lang auto` | تشخیص از یک صفحه | `fas`, `ara`, `fas+ara` هم قابل قبول است |
| `--index-type auto` | SQ بالای ۵۰ هزار بردار | زیر آن اسکن ساده سریع‌تر است |
| `--rerank heuristic` | خاموش | در مجموعه آزمون سود نشان نداد (فقط کندتر) |

## اعداد اندازه‌گیری‌شده

- OCR: **۳۰۰ صفحه در ۱۶.۶s** (۱۸.۱ صفحه/ثانیه، `fast`)؛ `best` همان کار در ۲۹.۴s.
- دقت روی ۶۰ صفحه نمونه: `fast` **۹۳.۱٪**، `best` **۹۴.۰٪**.
- ایندکس ۲۰۰ هزار بردار ۳۸۴بعدی: `IVF_HNSW_SQ` جست‌وجو را از ۵۰۹ms به **۱۰.۶ms** می‌برد (۴۸×؛ +۳۷٪ فضای دیسک).
- صف سراسری OCR: ۸ کتاب کوچک ۴.۱۶s → **۱.۳۹s** (۳×).
- کورپوس افزایشی: بازسازی ۰.۴s در برابر **۰.۱s** روی ۱۵۰۰ تکه، و با رشد کورپوس این شکاف باز می‌شود.

## سلامت و کیفیت

هر کتاب در مانیفست `data/library.json` این‌ها را دارد: `pages`, `ocr_pages`, `chars`,
`chars_per_page`, `failed_pages`, `warnings` و `content_key` (برای تشخیص کپی).
هشدارهای کیفیت (`thin-text`, `many-empty-pages`, `failed-pages`) هم در کنسول چاپ
می‌شوند و هم در خروجی JSON — با هزار کتاب، این تنها راه پیدا کردن کتاب‌های خراب است.

صفحه‌ای که لایه متنی دارد ولی متنش بی‌معنی است (نگاشت غلط یا برعکس) خودکار OCR
می‌شود؛ لایه متنی خراب هرگز به‌عنوان متن سالم پذیرفته نمی‌شود.

## محدودیت‌ها

- برچسب زبان به‌ازای کتاب است، پس کتاب فارسی با نقل‌قول عربی `mixed` می‌شود؛ برای
  شامل‌کردنش `--lang fa --lang mixed` بده.
- `psm` ثابت است؛ برای کتاب دوستونه کیفیت پایین می‌آید.
- ایندکس برداری زیر ۵۰ هزار بردار ساخته نمی‌شود (عمدی).
- بازرتبه‌بندی روی مجموعه برچسب‌دار سود نشان نداد؛ پیش‌فرض خاموش است.
