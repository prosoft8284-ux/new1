# وضعیت بازنویسی بانک ۴۰۰۰ سؤالی

آخرین به‌روزرسانی: rs2 (بازچینش سبک، فایل نظریه، سؤال ۱ تا ۵۸)

## سبک هدف (اندازه‌گیری‌شده از دفترچه‌های ۱۱۰۸ و ۱۰۸۱)
پروفایل کامل: `tmp/exam/style-profile.md`. خلاصه:
- صورت سؤال بلند (میانه ۷۰–۷۶ کاراکتر)، گزینه کوتاه و برچسبی (میانه ۱۵–۱۷)، پراکندگی طول گزینه ۴–۲۰.
- فرم غالب «کدام…» (۴۰–۸۲٪)، «هیچ‌کدام/همه/هر دو» صفر.
- در بانک برعکس است: کلید یک جملهٔ بلند است و ۴۸–۹۴٪ مواقع بلندترین گزینه.

## روش جاری: بازچینش سبک (نه بازنویسی کامل)
1. `node tools/dump-restyle.js <۱..۵> <از> <تعداد>` → سؤال‌ها به ترتیب شماره با متن کلید و سه گزینهٔ دیگر.
2. نوشتن `tools/rewrites/restyle/rsN.json` با ساختار `{ "file.txt": { "شماره": { "key": "برچسب کوتاه" } } }`
   (اختیاری `"stem"` هم پذیرفته می‌شود).
3. قاعده: کلید به برچسب ۲۰–۴۰ کاراکتری هم‌اندازهٔ سه گزینهٔ دیگر فشرده می‌شود؛ شمارهٔ کلید و متن تحلیل دست نمی‌خورد.
   اگر کلید از قبل کوتاه و هم‌اندازه بود (مثل «آگوست کنت»)، تغییر نمی‌کند.
4. `node tools/apply-restyle.js tools/rewrites/restyle/rsN.json`
5. چهار بررسی: `check.js` / `dups.js` / `npm test` / `audit-quality.js`.

## برنامهٔ مبتنی بر روز کنکور (۱۶ اردیبهشت) + APK تازه
- منطق «۱۷۰ روز از شروع» برداشته شد. تاریخ شروع را کاربر می‌زند و اپ فاصله تا ۱۶ اردیبهشت را حساب می‌کند (`SBCore.examInfo`) و ۱۷۰ روز محتوا را روی همان تعداد روز می‌چیند (`SBCore.planSchedule`): اگر تقویم کوتاه‌تر باشد چند روز دو برنامه می‌گیرد و اگر بلندتر باشد روزهای اضافه «مرور و تثبیت» می‌شوند. روز آخر برنامه همیشه روز کنکور است.
- تبدیل تاریخ شمسی/میلادی (`g2j`/`j2g`) و چیدن برنامه در `app/core.js`؛ ۴ تست تازه (جمع ۱۵ تست سبز).
- صفحهٔ «امروز» نوار «تا کنکور» و شمارش روز/کل روزها را نشان می‌دهد؛ صفحهٔ برنامه و راهنما و `plan.html` هم به همین منطق به‌روز شدند. کش `app/sw.js` به `sb-v10`.
- APK با JDK 21 + Android SDK 36 ساخته شد: `apk/soalat-4000-konkoor.apk` (۵٫۰M، Capacitor ۸، debug).
